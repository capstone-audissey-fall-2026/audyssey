# 현재 상태: 남은 과제와 실측 기록

뼈대 단계에서 확인한 한계와 측정값입니다. 단계별 시간, 메모리, 해결한 문제는
[설계 문서 §13](superpowers/specs/2026-11-09-audyssey-skeleton-design.md#13-미결정--확인-필요)에 있습니다.

## 모듈별 남은 과제

### 오케스트레이터·API
- 소스를 차례로 하나씩 분리합니다(`graph.py`의 `ponytail:` 표시). GPU 도구를 늘리면 병렬로 바꿀 수 있습니다.
- 서버 프로세스는 1개이고 작업 큐, DB, 사용자 인증이 없습니다. SSE는 저장된 작업을 주기적으로 읽어 보냅니다.
- 자연어 편집 입력(명령 번역)은 아직 없습니다.
- 검수에서 걸려 계획을 다시 세우면, 이름이 바뀐 소스는 새로 만들어집니다. 분석 중에 바꾼 볼륨 같은 편집이 사라집니다.

### UI
- 화면(`/`)은 `web/`의 React 앱입니다(SoundPilot 화면을 이식). 영상과 시각 단서 강조, 트랙별 재생·Solo·파형·음량(0~200%)·켜고 끄기·피치, span 끌어서 고친 뒤 "Regenerate with new spans", 새 트랙(소스 추가), 계획 패널, 자연어 편집 바, 접이식 파이프라인 board와 단계별 모델 입력·출력, 내보내기를 지원합니다. 화면 문구는 영어입니다.
- 빌드하지 않은 체크아웃에서는 `/`가 이전 단일 파일 화면으로 대체되고, 이전 화면은 `/legacy`에도 있습니다. 개발용 화면은 `/dev`입니다.
- 진행 중인 모델 호출의 입력은 호출이 끝난 뒤에 보입니다.
- 생성 소스의 span은 읽기 전용입니다(생성기가 span을 쓰지 않습니다).
- 2단계(`contracts.py` 변경, 팀 합의 필요): 클립 자르기·옮기기, span 밖 무음 처리, 트랙 삭제 명령, 음량 400%, 프로젝트 이름·날짜.

### 플래닝
- 기본 입력(`frames`)은 프레임 이미지만 봅니다. 오디오까지 보려면 `video` 입력과 `AUDYSSEY_PLANNER_VIDEO_AUDIO=true`(Gemini, Qwen-Omni)를 씁니다. 전사는 아직 쓰지 않습니다.
- 기본 vLLM 모델(Qwen2.5-VL-3B)은 품질이 낮습니다. 예: 2라운드 뒤 소스가 1개만 남음.
- OpenRouter로 부르면 fps를 지정할 수 없어 1fps로 들어갑니다. 소리는 전달됩니다([실측](#플래너-호출-방식-2026-11-17)).
- Gemini 직접 호출은 클립을 Files API로 올린 뒤 부르므로 호출마다 몇 초 더 걸립니다.
- 계획·검수는 분리의 실제 오디오 근거와 생성의 장면 적합성을 구분합니다. 분리 검수는 기본으로 PCM WAV만 전달하고, 디지털 무음 구간은 모델 호출 전에 제외합니다. 형식 오류·불확실·오디오 입력 부재는 승인되지 않으며, 한도 뒤에도 미검증인 소스는 건너뜁니다. 실제 영상의 누락률과 시간 경계 정확도는 추가 평가가 필요합니다. [정책·실행법](planning.md), [합성 대조 평가](../evals/planning/report.md).

### 분리
- 재시도할 때 `attempt`를 시드로만 씁니다. 필터링이 `suggestion`을 주지 않으므로 사실상 같은 조건으로 다시 분리합니다.
- 후보 고르기는 기본으로 꺼져 있습니다(후보 1개). ImageBind 파일은 Compose에 마운트하지 않았습니다.
- 도구 서버마다 모델 1개, 요청 1개씩 처리합니다. 첫 호출 때 모델을 올리므로 첫 요청이 느립니다.

### 필터링
- 합격 여부는 도구 서버가 돌려준 점수로 앱이 정합니다. 기준값은 앱 `.env`의 값이 쓰입니다. 도구 쪽에 남은 기준 비교 코드는 정리 전입니다.
- 합격 기준 기본값은 3.0입니다. Judge overall(1~5 범위) 실측으로 정했습니다([보정 기록](#judge-합격-기준-보정-2026-11-27)).
  - 표본이 영상 1개라 확정값이 아닙니다. 영상을 늘려 다시 확인합니다.
    - 표본에는 ambience stem이 없습니다. 이전 `sam-audio-small` 실행에서는 ambience가 약 3.2, 대사와 효과음이 약 1.0이었습니다. ambience가 많은 영상이나 small 모델에서 정상 stem이 실패하면 기준을 2.5로 낮춥니다.
  - Judge는 영상에 없는 그럴듯한 소리를 걸러내지 못합니다. 합격은 Judge가 분리 결과를 설명과 맞다고 판단했다는 뜻이고, 그 소리가 영상에 있다는 증거가 아닙니다.
- 실패 이유와 수정 조건(`suggestion`)을 만들지 않습니다.

### 그라운딩
- 시각 힌트는 기본으로 꺼져 있습니다. 텍스트 설명이 있으면 마스크가 분리 결과를 거의 바꾸지 못했습니다([시각 힌트 효과](#시각-힌트-효과)). 같은 성별 두 사람처럼 텍스트로 구분하기 어려운 장면에서만 켤 만합니다.
- 힌트 박스를 함께 주기 때문에 SAM3는 박스 안에서 거의 항상 무언가를 찾습니다. 없는 대상도 찾았다고 나와서 검증 효과가 약합니다.
- 마스크는 대상만 남기고 나머지를 검게 칠합니다. SAM Audio의 `mask_videos`는 반대로 대상을 지우지만, 공식 벤치마크 화자 쌍에서 마스크가 효과를 낸 경우는 모두 우리 방식이었습니다. 코드를 `mask_videos` 방식으로 바꾸지 마세요.
- 아주 작은 대상을 추적하다 놓치면 마스크 전체가 실패합니다(`No points are provided`). 그 소스만 실패하고 작업은 계속됩니다.
- 메모리 때문에 2fps로 추적합니다. CUDA에서만 돕니다.

### 편집·합치기
- 피치 변경은 ffmpeg `asetrate`+`atempo`를 쓰는 단순한 방식입니다.
- 영상에 들어가는 오디오는 AAC라 손실 압축됩니다.
- 구간별 편집이나 페이드 기능은 없습니다.

### 인프라·배포
- RunPod 템플릿을 실제 Pod에서 띄워 보지 않았습니다.
  - 필요한 GPU 메모리는 sv3 Compose 측정값에서 vLLM 몫(약 16GB)을 뺀 추정입니다. 기본 설정에서 약 34GB, 시각 힌트를 켜면 약 53GB입니다.
  - [가중치 다운로드 목록](running.md#가중치-준비)은 sv3에서 그 목록만 담은 캐시로 확인했습니다. 빈 RunPod 볼륨에 처음부터 받아 보지는 않았습니다.
- GPU 이미지는 빌드 중 큰 git 의존성 다운로드가 자주 끊겨 최대 5번 다시 시도합니다.
- CI 필수 검사는 `lint-and-format-check`, `numpy-1x`, `docker-build` 3개입니다. GPU 실측은 CI에 없습니다.

### 플래너 호출 방식 (2026-11-17)

10초 전기톱 영상, `gemini-3.8-flash`. 입력 토큰으로 fps와 소리 전달을 확인했습니다.

| 요청 | 입력 토큰 |
|---|---|
| OpenRouter, 소리 있음 | 978 |
| OpenRouter, 소리 뺀 영상 | 726 |
| Gemini 직접 호출, fps 1 | 978 |
| Gemini 직접 호출, fps 2 | 1638 |

- OpenRouter는 소리를 전달하고 fps는 1로 고정됩니다. OpenRouter 영상 형식에는 fps 항목이 없어 Gemini 기본값 1.0이 쓰입니다.
- 소리를 뺀 영상에서도 모델이 대사와 소리를 지어냈습니다. 답변만으로는 소리를 들었는지 판단할 수 없습니다.
- 파리 영상(7.1초) 플래너·검수기 시간: OpenRouter 8.5초·6.7초, Gemini 직접 호출 23초·41초(검수기도 Gemini).
- GHCR `c0ee48e`(PR #34·#35·#36 합본), sv3-a100 GPU 1장, Gemini 직접 호출 플래너 + vLLM Qwen3-VL-8B 검수기, 모델 로딩 포함 첫 실행: 무음 생성 86초, 파리 영상 분리 184초, 다시 분리 25초. 서버 상태 표시 모두 정상.

### Judge 합격 기준 보정 (2026-11-27)

sam-audio-large-tv + sam-audio-judge, 영상 `sp-explainer` 1개(job `01f28c2d3ff2`)의 실측입니다. 정상은 planner 설명이 영상의 실제 소리와 맞는 stem 5건(소스 4개, sfx는 같은 소스의 다른 구간이라 2번 센 것)이고, 사람이 듣고 확인한 것은 아닙니다. 틀린 설명은 같은 소스(sword)에 설명만 바꿔 넣었습니다.

| 설명 | overall | 비고 |
|---|---|---|
| 정상 stem 5건 (소스 4개: music, dialogue 2, sfx 1 — sfx는 구간 2개) | 3.83, 3.91, 4.22, 4.25, 4.76 | 평균 4.19 |
| church bells ringing (틀린 설명) | 1.80, 1.58, 1.30 | 재시도할수록 낮아짐 |
| a baby crying loudly (영상에 없는 소리) | 4.18 | 걸러지지 않음 |

| 기준 | 정상 stem 실패 | church bells |
|---|---|---|
| 0.5 (이전) | 0/5 | 통과 |
| 2.5, 3.0, 3.5 | 0/5 | 실패 |
| 4.0 | 2/5 | 실패 |

- 3.0은 정상 최저(3.83)와 틀린 설명 최고(1.80) 사이이고, 정상 최저보다 0.83 낮아 표본 밖 stem에도 여유가 있습니다. 4.0은 정상 stem을 실패시키므로 쓰지 않습니다.
- 사각지대: baby crying처럼 영상에 없지만 그럴듯한 소리는 overall 4.18(recall 5.05, faithfulness 5.00)로 4.0에서도 통과합니다. 점수 기준만으로는 이 경우를 거를 수 없습니다.
